# Feature Specification: 图片模态协议补齐

**Feature Branch**: `007-image-modal-protocol`

**Created**: 2026-08-24

**Status**: Draft

**Input**: User description: "当前项目，对图片生成、图片识别的处理还没做，我们来完善吧"

## Clarifications

### Session 2026-08-24

- Q: 当选中的非透传源无法映射图片生成工具时，网关应该把这次转换失败当作该源
  失败并继续尝试后续源，还是立即终止整轮请求？ → A: 该源失败并按既有顺序尝试
  其他源；全部不可用时返回转换错误。
- Q: 非透传源在回灌历史中已完成的生成图像时，应该怎样处理图像本体？ → A:
  始终携带全部已完成生成图像本体。
- Q: 当图片出现在系统或开发者指令里，而目标协议不支持在该位置携带图片时，网关
  应该如何处理这个源？ → A: 该源转换失败并可换源；全部不可用时返回明确错误。
- Q: 当某个模型被配置为不接受图片输入时，网关应该只把它公告为纯文本模型，还是
  继续拦截仍带图片的请求？ → A: 只公告纯文本；带图请求仍映射转发，由上游决定。
- Q: 诊断日志记录图片地址时，应该如何处理 URL 里的查询参数和片段？ → A: 抹掉
  查询参数和片段，保留基础地址。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 图片识别输入完整到达上游 (Priority: P1)

用户向网关发送一条包含图片的对话请求。图片可以是对外可访问地址，也可以是内嵌
数据的地址；图片出现在用户消息或工具结果等目标协议允许承载视觉内容的合法位置。
网关必须把图片转换成所选上游契约的原生视觉内容槽位，不能把图片替换成普通文本占位，
也不能让模型只看到“有一张图”却看不到图本身。

**Why this priority**: 图片识别是多模态会话的基础能力；识别失败会让用户可见输入
丢失，并直接导致模型答非所问。

**Independent Test**: 分别用 URL 图片和内嵌数据图片发起请求，检查选中后端收到的
请求包含等价图片内容，且客户端能收到基于该图片的正常回答。

**Acceptance Scenarios**:

1. **Given** 用户消息含 URL 图片和文本，**When** 请求命中任一已配置源，**Then**
   上游收到与该图片等价的原生内容项，文本顺序保持可理解，客户端收到正常 SSE 响应。
2. **Given** 用户消息含内嵌数据图片，**When** 请求命中任一已配置源，**Then**
   上游收到同一图像数据，网关不要求外部文件服务可达。
3. **Given** 工具结果内容数组中包含图片，**When** 该结果需要回灌到上游，**Then**
   上游在协议允许的位置看到该图片；相邻文本和调用关联关系保持可用。
4. **Given** 上游返回拒绝、空答案或格式限制，**When** 网关转发结果，**Then**
   客户端看到上游真实结果或错误，网关不代为判定“该模型一定不支持图片”。

---

### User Story 2 - 透传源的图片生成端到端可用 (Priority: P2)

用户向上游原生支持图片生成的透传源请求生成图片。客户端声明图片生成工具及其选项，
上游按自身规则产生进度、局部图或完成事件。网关必须保持该工具契约端到端原样可用：
请求形状不被降级成普通函数，生成结果不被丢弃，后续多轮回灌仍能让上游认得历史生成
调用。

**Why this priority**: 这是唯一能让网关提供真实图片生成的路径；破坏透传会把可用
能力变成不可用。

**Independent Test**: 向一个支持 Responses 图片生成的上游发起生成请求，验证客户端
可收到完成结果中的图像数据；再带历史生成结果发起追问，验证上游仍能理解该历史。

**Acceptance Scenarios**:

1. **Given** 客户端声明图片生成工具，**When** 请求命中透传源，**Then** 上游收到
   该工具声明和可选参数，响应中的进度、局部图、完成事件与最终图像数据保持可用。
2. **Given** 上游返回完成图像，**When** 客户端保存或展示结果，**Then** 图像编码
   与调用标识未被改写，客户端不需要依赖额外平台资源即可使用结果。
3. **Given** 上一轮包含完成的图片生成调用，**When** 客户端自带完整历史再次请求，
   **Then** 透传源收到可识别的历史生成调用和结果。
4. **Given** 上游不支持所声明的生成选项，**When** 上游返回错误，**Then** 网关按
   既有失败语义返回该错误并允许调度器按既有规则处理，不伪造成功或空白图像。

---

### User Story 3 - 非透传源的图片边界清晰且历史不失真 (Priority: P3)

用户把同一客户端请求发到没有原生图片生成契约的上游类型。网关必须在请求前给出明确
的源级协议不可映射判定，而不是把生成工具伪装成普通函数、编造图片或等待上游误判；
随后按既有调度语义尝试其他源。若历史里已有真实生成图像且目标协议有原生图片槽位，
网关必须把全部图像本体作为有损上下文带入，但必须保留“这是先前生成结果”的
可理解线索，不得冒充用户新上传图片。

**Why this priority**: 这类源无法安全触发真实生成，但清晰的边界和多轮图像上下文
仍比静默丢弃更可预测。

**Independent Test**: 用图片生成声明请求只含非透传源的配置，验证该源在调用上游前
失败且整轮收到确定性转换错误；再用非透传源加透传源的混合配置验证可按既有规则换源；
最后用包含已完成生成图像的历史请求非透传源，验证图像以有损上下文进入原生图片槽位
或按矩阵明确登记损失。

**Acceptance Scenarios**:

1. **Given** 请求声明图片生成工具或强制选择该工具，**When** 目标是非透传源且其
   协议无原生等价工具，**Then** 网关在调用该上游前产生源级协议映射失败；若存在
   兼容源则按既有调度规则继续尝试，客户端最终获得成功结果或整轮确定性错误。
2. **Given** 历史包含完成的图片生成调用及图像数据，**When** 目标协议支持图片输入，
   **Then** 网关将每个完成结果的图像本体放入原生视觉槽位，并以英文 wire 文本
   标明它是先前生成结果；生成元数据缺失时在覆盖矩阵登记。
3. **Given** 历史图像没有可在目标协议安全承载的槽位，**When** 转换发生，**Then**
   系统输出结构化告警并在覆盖矩阵登记丢弃影响，不伪造终态或图像。
4. **Given** 仅包含外部平台文件引用而网关无权取回，**When** 目标是非透传源，**Then**
   网关对该源产生明确的协议不可映射失败并允许继续尝试其他源；透传源则原样保留
   该引用交由上游解析。

### Edge Cases

- 同一请求混有多张图片、多种引用方式：每张图片独立判断可映射性；任一图片在某个
  非透传源不可映射时，该源不得发送丢失内容的残缺请求，而应作为源级失败进入既有
  换源流程。
- 图片位于系统或开发者指令中：目标协议不允许时不得挪动到用户角色伪装语义；该源
  按协议不可映射失败处理并允许既有换源流程继续；全部候选源不可用时返回明确错误。
- 图片数据超大或格式不受目标端支持：由上游决定接受、压缩、拒绝或报错；网关不因
  推测模型能力提前拒绝。
- 生成过程只有状态事件、没有最终图像：客户端收到上游真实生命周期或既有空流/
  失败语义，网关不合成图像。
- 局部图与最终图同时出现：客户端能看到渐进结果；最终图缺失时不得把局部图改写为
  最终完成结果。
- 历史生成调用缺少结果：只保留可安全表达的提示、状态或标识线索；缺失影响必须可
  观测，不得虚构图像。
- 多源故障转移跨越不同上游契约：图片生成声明在某个非透传源的转换失败属于该源级
  失败；尚未锁定源或向客户端发出生成事件时，按既有规则尝试后续源；一旦已锁定或
  发出生成事件/终态，不得换源重放。
- 外部图片地址临时不可访问：网关不做代理拉取兜底；上游能否访问和如何报错归上游。
- 图片地址携带签名或令牌等查询参数：诊断日志只保留基础地址（协议、主机、路径），
  查询参数、片段和完整数据本体不进入日志。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将用户消息和工具结果中的图片识别输入映射到所选目标协议的
  原生视觉内容槽位；URL 与内嵌数据图片均 MUST 保持图像本体可用。
- **FR-002**: 对具备原生视觉槽位的非透传协议，仅包含外部平台文件引用的识别输入
  MUST 触发明确的源级协议不可映射失败并进入既有换源流程，MUST NOT 静默替换为文本
  占位；透传协议 MUST 原样保留该引用。
- **FR-003**: 图片识别的展示控制字段在没有目标等价字段时 MAY 丢弃；系统 MUST 在
  协议覆盖矩阵登记损失，且 MUST NOT 因控制字段无法映射而丢弃图像本体。
- **FR-004**: 系统 MUST 支持透传源上的图片生成工具声明、生成选项、工具强制选择、
  进度事件、局部图事件、完成事件和历史生成调用回灌。
- **FR-005**: 透传路径返回的生成结果 MUST 保留原始图像编码、调用标识、状态和事件
  顺序；网关 MUST NOT 合成、裁剪、转存或改写为另一种产物形态。
- **FR-006**: 对没有原生图片生成工具契约的非透传协议，系统 MUST 在调用该上游前
  产生明确的源级协议不可映射失败；调度器 MUST 按既有规则继续尝试后续可用源。
  仅当本轮没有可安全映射的候选源时，客户端 MUST 收到确定性协议映射错误。系统
  MUST NOT 把生成工具降级为普通函数或编造生成结果。
- **FR-007**: 对历史中每一个已完成的真实生成图像，若目标协议存在原生图片输入
  槽位，系统 MUST 以有损上下文方式完整携带该图像本体，并用英文 wire 文本说明其
  为先前生成结果；系统 MUST NOT 额外按数量或单图大小选择性裁剪。既有请求体上限
  仍适用于整笔请求。该映射 MUST 在协议覆盖矩阵标记为有损。
- **FR-008**: 历史生成调用的提示、状态、标识或结果部分缺失时，系统 MUST 只携带可
  安全表达的部分；重要图像结果被丢弃时 MUST 输出结构化告警并登记影响。
- **FR-009**: 图片相关请求的失败 MUST 使用既有错误或 SSE 错误终态语义；系统 MUST
  NOT 为了图片场景引入新的成功假象、静默断流或绕过调度锁定规则。
- **FR-010**: 每条上游类型的图片输入、图片生成工具、历史回灌和出站事件状态 MUST
  在协议覆盖矩阵中分别登记，禁止跨路径复用状态。
- **FR-011**: 图片引用、文件标识、调用标识和错误上下文 MUST 可用于诊断；图片 URL
  入日志前 MUST 抹掉查询参数和片段、只保留基础地址；内嵌数据图片 MUST 只记录类型
  和大小等元数据。日志和观测 MUST NOT 记录凭据、完整大体积图像数据或被脱敏的
  URL 参数。
- **FR-012**: 系统或开发者指令中的图片在不支持该位置的目标协议中 MUST 触发该源
  的协议不可映射失败；调度器 MUST 按既有规则尝试后续可用源。系统 MUST NOT 只丢
  弃图片后把残缺指令发给该上游。
- **FR-013**: 模型的“不接受图片”配置 MUST 只控制对外模型目录中的输入模态公告；
  客户端仍发送图片时，系统 MUST 继续按所选上游契约做协议映射并把请求交给上游，
  MUST NOT 因该公告在转发路径新增能力拦截。

### Key Entities

- **图片识别输入**: 用户或工具结果带给模型的视觉证据；关键属性包括图像本体或外部
  引用、所在消息角色、展示控制和与其他内容的顺序。
- **图片生成调用**: 上游执行图片生成的请求与结果；关键属性包括工具声明与选项、
  调用标识、生命周期状态、局部图、最终图像编码和错误。
- **上游契约类别**: 决定同一图片数据走语义映射还是最小透传；不同类别的覆盖状态
  必须独立维护。
- **有损历史上下文**: 先前生成结果在新一轮对话中的可理解表达；关键属性是图像本体、
  来源说明、保留的元数据和明确登记的损失。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对三类受支持的图片识别样例（URL、内嵌数据、工具结果图片），100% 的
  合法请求能在对应上游请求中找到等价图像内容，且客户端回答与图像相关。
- **SC-002**: 透传源的生成链路中，工具声明、全部生成事件和完成图像的保真度达到
  100%；连续 20 次端到端样例不出现图像丢失、顺序错乱或合成占位图。
- **SC-003**: 无原生生成契约的非透传源对生成声明 100% 在调用该上游前产生源级
  协议映射失败；当存在兼容源时请求可成功，当全部候选源不可用时客户端 100%
  收到确定性协议映射错误。
- **SC-004**: 含历史生成图像的多轮样例中，具备视觉槽位的非透传源能收到全部图像
  本体与来源说明；无槽位场景的结构化告警覆盖率 100%。
- **SC-005**: 三条上游路径的图片覆盖状态互不串用；协议矩阵、用户文档和验收样例
  对同一行为的描述完全一致。
- **SC-006**: 图片相关错误、跳过和终态在观测中可归因到路径与原因；凭据和大体积
  图像数据泄露次数为 0。
- **SC-007**: 含系统或开发者指令图片的请求在支持该位置的目标路径中保留完整视觉
  语义；在不支持的位置产生源级映射失败，且不会向该上游发送丢失图片后的残缺指令。
- **SC-008**: 配置为纯文本公告的模型收到带图请求时，100% 不被网关新增能力拦截；
  上游请求仍包含等价图像内容，最终结果或错误来自上游。
- **SC-009**: 日志中的图片地址 100% 为基础地址，不含查询参数、片段或数据本体；
  含签名参数与内嵌数据图片的两种样例均覆盖日志脱敏断言。

## Assumptions

- 本特性补齐的是网关的协议处理，不新增图像生成模型、文件存储、图片代理或本地
  session store。
- 上游是否真正支持某个模型或图片选项，始终由上游运行时决定；网关只区分“协议是否
  有安全槽位”。
- 模型目录的纯文本公告是客户端选择提示，不是转发路径的能力裁判；真正的接受、拒绝
  或格式限制由上游决定。
- 透传源是最先获得真实图片生成端到端能力的路径；非透传源若无原生等价工具，只能
  得到明确边界和有损历史上下文。
- 外部平台文件引用不在网关侧取回或缓存；能否解析取决于所选上游。
- 完整回灌生成历史会保留全部图像本体；整笔请求是否超过容量仍由既有入站请求体
  上限约束，网关不为图片场景另设裁剪策略。
- 现有图片识别基础可以纳入本特性统一验收，但不改变其已经验证过的正确映射方向。
