# Feature Specification: 子 Agent 对话归属修复

**Feature Branch**: `001-subagent-conversation-repair`

**Created**: 2026-08-18

**Status**: Draft

**Input**: User description: "当前子 agent 处理有问题；子 agent 执行后，对话出现问答不对应。此前已经处理过子 agent 链路，但当前结果仍有问题，需要用 codex app-server 测试并修复。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 单个子 Agent 对话保持对应 (Priority: P1)

用户向主 agent 提出一个会触发子 agent 的任务。子 agent 必须收到且只收到属于它的任务；子 agent 的过程消息和最终答复必须归属于该子 agent；主 agent 的汇总答复必须等子 agent 结果返回后，再作为主 agent 的回复呈现给用户。

**Why this priority**: 该场景是用户报告的最小复现。只要父/子回复仍然串接，用户就无法信任任何多 agent 结果。

**Independent Test**: 构造一个包含主 agent、一个子 agent、明确不同的任务文本和明确不同的答复文本的对话场景，检查每条任务和答复都能对应到正确 agent。

**Acceptance Scenarios**:

1. **Given** 用户请求主 agent 派发一个子任务，**When** 子 agent 完成任务并返回最终答复，**Then** 子任务文本只出现在该子 agent 的上下文中，最终答复只归属于该子 agent。
2. **Given** 子 agent 已返回结果，**When** 主 agent 生成汇总，**Then** 汇总归属于主 agent，并引用或使用正确的子 agent 结果。
3. **Given** 用户随后继续提问，**When** 主 agent 基于历史回答，**Then** 新回答对应用户新问题，且不会把旧问题、子 agent 答复或主 agent 汇总错误配对。

---

### User Story 2 - 并发子 Agent 不串话 (Priority: P2)

用户请求主 agent 同时派发多个子 agent。每个子 agent 都必须获得自己的任务，过程消息、完成状态和最终答复必须分别归档到对应会话，不能因为并发、完成顺序不同或消息交错而串到其他 agent。

**Why this priority**: 并发是多 agent 的核心价值，也是问答错位最容易暴露的场景；单 agent 修复不能证明并发安全。

**Independent Test**: 同时派发至少两个带有唯一任务标识和唯一答复标识的子 agent，强制其完成顺序与派发顺序不同，再检查全部任务、过程消息和答复的归属。

**Acceptance Scenarios**:

1. **Given** 两个子 agent 分别收到任务 A 和任务 B，**When** 任务 B 先完成，**Then** 任务 B 的答复仍归属于任务 B 的子 agent，不会被误认为任务 A 的结果。
2. **Given** 多个子 agent 的过程消息交错到达，**When** 用户查看任一子 agent 会话，**Then** 该会话只包含此 agent 的任务、状态和答复。
3. **Given** 所有子 agent 完成，**When** 主 agent 汇总，**Then** 汇总中的每个结论都来自对应子 agent 的正确答复。

---

### User Story 3 - 回归定位与可信修复 (Priority: P3)

维护者需要确认这次问题发生在哪一层：Codex 客户端编排、网关转换、上游返回，或历史回灌。修复必须基于可复现证据，并保留此前已经验证过的子 agent 任务投递能力。

**Why this priority**: 该问题已经有历史修复，继续叠加猜测式补丁会扩大协议风险。可信的边界证据和回归测试比单纯让单个用例通过更重要。

**Independent Test**: 使用可自动化的 Codex 对话服务入口记录父/子请求、响应和最终会话历史，先定位错位发生的边界，再验证修复后的完整对话序列。

**Acceptance Scenarios**:

1. **Given** 一个可稳定复现的父/子对话脚本，**When** 记录各层输入和输出，**Then** 能指出问答错位首次发生的位置。
2. **Given** 已定位到网关负责的错位，**When** 实施修复，**Then** 自动化回归测试覆盖该错位场景并保持所有既有子 agent 投递测试通过。
3. **Given** 证据显示错位由外部组件产生，**When** 网关收到相关请求，**Then** 网关仍按协议原样传递结果，不代外部组件编造或改写答案。

### Edge Cases

- 子 agent 失败或被取消时，主 agent 必须收到可识别的失败状态，不能把其他子 agent 的答复或旧答复当作替代结果。
- 子 agent 返回空答复时，空状态必须保留为空，不能被转换成成功答复或错误答复。
- 同名工具调用、重复任务标识或交错消息不能造成父子历史错配。
- 主 agent 在子 agent 完成前被中断时，已产生的消息必须保持原有归属，不能在后续续话时改挂到其他 agent。
- 用户在子 agent 执行期间继续提问时，新问题必须保留在自己的对话位置，不能插入或覆盖子 agent 的任务上下文。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 保持主 agent 与子 agent 的会话边界，使任务、过程消息、完成状态和最终答复始终归属于产生它们的 agent。
- **FR-002**: 系统 MUST 在子 agent 返回后把结果送回发起该子任务的主 agent，且不得改变结果的发起方、接收方或完成顺序语义。
- **FR-003**: 系统 MUST 保证主 agent 的汇总答复在用户对话中归属于主 agent，并只使用正确归属的子 agent 结果。
- **FR-004**: 系统 MUST 保证用户后续提问基于正确的历史顺序，不得把旧问题、子 agent 答复或主 agent 汇总错误配对。
- **FR-005**: 系统 MUST 支持多个子 agent 并发执行，并在消息交错或完成顺序与派发顺序不同的情况下保持一一对应。
- **FR-006**: 系统 MUST 保留此前已支持的子 agent 任务投递能力，包括任务文本完整送达和 collaboration 工具的既有处理结果。
- **FR-007**: 系统 MUST 将子 agent 失败、取消、空答复和中断作为明确状态处理，不得用其他 agent 的内容、旧内容或编造内容替代。
- **FR-008**: 维护者 MUST 能够通过可自动化的 Codex 对话服务入口复现、记录和验证父/子对话归属，验收证据必须包含最终会话历史。
- **FR-009**: 修复 MUST 覆盖当前所有受支持的上游转换路径；任一路径与其它路径行为不同时，必须在协议覆盖事实源中记录差异。

### Key Entities

- **主 agent 会话**: 用户直接交互的对话上下文，包含用户问题、主 agent 汇总和它派发的子任务引用。
- **子 agent 会话**: 由主 agent 创建的独立任务上下文，包含初始任务、过程消息、用户可见状态和最终答复。
- **Agent 消息**: 父子 agent 之间传递的任务、通知、续任务和最终答复，必须保留发送方、接收方和所属会话。
- **对话归属**: 一条消息或答复与主 agent、子 agent 或用户的对应关系，是本特性必须修复的核心数据语义。
- **执行状态**: 子 agent 的进行中、完成、失败、取消和空结果状态，必须与其所属会话一起传递。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 单个子 agent 端到端场景中，任务、过程消息、最终答复、主 agent 汇总和后续问答的归属正确率达到 100%。
- **SC-002**: 至少两个子 agent 并发且完成顺序与派发顺序相反的场景中，任务与答复错配数量为 0。
- **SC-003**: 现有子 agent 任务投递、工具识别和历史回灌回归测试全部通过，不因本次修复引入新的失败。
- **SC-004**: 自动化验收能重复运行 3 次并得到相同的父子对话归属结果。
- **SC-005**: 修复前的证据能明确指出问答错位首次发生的系统边界，修复后的证据能展示完整最终会话历史无错配。

## Assumptions

- Codex 多 agent 编排仍由 Codex 客户端负责创建和驱动子 agent，网关只处理客户端发出的对话请求、工具调用和历史回灌。
- 本特性修复当前已支持上游路径中的问答归属回归，不新增新的 agent 编排运行时。
- 验收将使用用户指定的 Codex app-server 可自动化入口；该入口仅作为测试方式，不改变本规格的产品目标。
- 子 agent 的任务和答复文本可以使用唯一标记构造，测试重点是对应关系，不依赖特定业务内容。
- 若定位证明错位完全来自外部组件，本特性的交付物是边界证据和网关侧不破坏协议的验证，而不是替外部组件编造结果。
