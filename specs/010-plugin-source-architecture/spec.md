# Feature Specification: 插件式上游源架构

**Feature Branch**: `010-plugin-source-architecture`

**Created**: 2026-08-26

**Status**: Draft

**Input**: User description: "整理架构，采用清晰的插件式架构，把 Copilot 后端相关能力完全收拢到一个自治源插件中；共享核心不感知该源的专属类型、字段或文案，并让后续新增其他源更容易。配置格式做一次干净的破坏性升级，不做旧格式兼容。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用命名源类型配置上游 (Priority: P1)

操作者用一个稳定、可读的源类型名称声明上游，例如 Anthropic、OpenAI Chat、OpenAI Responses 或 GitHub Copilot。该源的专属参数放在独立的扩展配置区域，通用连接参数与模型映射保持统一表达。

**Why this priority**: 配置是所有转发路径的入口。只有先把源身份和专属配置边界定义清楚，后续隔离、分发和管理功能才有稳定基础。

**Independent Test**: 准备四类内置源的最小合法配置，分别启动或热重载；系统应识别对应源类型并通过该类型的协议探测或请求验证。

**Acceptance Scenarios**:

1. **Given** 一个包含显式源类型和必属参数的源, **When** 系统加载配置, **Then** 该源进入可用源列表。
2. **Given** 源缺少名称、源类型或该类型声明的必填参数, **When** 系统加载或保存配置, **Then** 系统拒绝变更并指出源、字段和原因。
3. **Given** 配置仍使用旧短码风格或旧顶层专属字段, **When** 系统加载配置, **Then** 系统以明确的迁移错误拒绝启动，不自动猜测语义。

---

### User Story 2 - Copilot 行为由单一源插件承载 (Priority: P1)

管理员配置和使用 GitHub Copilot 时，认证、endpoint 解析、模型目录、协议路由、必要请求头和连通性检查都表现为同一个可插拔源的能力。共享调度、服务入口、配置核心、管理框架和健康检查框架不包含 Copilot 专属分支。

**Why this priority**: 这是本次改造的直接目标。只有把现有 Copilot 能力完整迁移到单一边界内，才能证明插件架构不是新的分层口号。

**Independent Test**: 使用模拟 Copilot 目录和三个委托协议端点发起请求，验证按模型支持端点选择协议、凭据和必要头正确传递、观测身份始终是 GitHub Copilot；再检查共享核心没有该源的专属标识。

**Acceptance Scenarios**:

1. **Given** Copilot 模型目录显示支持 Responses, **When** 客户端发送 Responses 请求, **Then** 系统通过 Responses 协议委托执行。
2. **Given** Copilot 模型只声明 Messages 或 Chat 端点, **When** 客户端发送 Responses 请求, **Then** 系统按既有优先级选择对应委托路径。
3. **Given** 模型目录暂时不可用, **When** 客户端指定有效 Copilot 模型, **Then** 系统保留既定回退路由行为，并将目录失败记录为诊断信息而不是伪造成功。
4. **Given** 管理员完成 Device Flow 授权, **When** 授权成功, **Then** 新凭据写入对应 Copilot 源的扩展配置区并经热重载生效。

---

### User Story 3 - 管理页按源能力渲染表单 (Priority: P2)

管理员新增或编辑源时，管理页根据当前系统公布的源类型描述和配置结构渲染通用字段与专属字段。选择不同源类型时，页面展示对应的必填项、可选项和扩展动作，不需要为每个源在共享页面里写死专属逻辑。

**Why this priority**: 管理页是本地用户的主要配置入口。动态能力描述能避免每新增一个源就修改共享界面。

**Independent Test**: 打开源编辑页切换四种内置源类型，确认字段可见性、必填校验、敏感值处理和扩展动作跟随所选类型变化；保存后刷新页面，值和脱敏状态保持正确。

**Acceptance Scenarios**:

1. **Given** 管理员选择普通 API 源, **When** 页面渲染表单, **Then** 必填地址和密钥字段出现，Copilot 扩展动作不出现。
2. **Given** 管理员选择 GitHub Copilot, **When** 页面渲染表单, **Then** 地址和普通密钥不再是必填项，授权动作和 Copilot 说明出现。
3. **Given** 已保存的源包含敏感专属值, **When** 管理页读取源列表, **Then** 响应不含明文凭据；空提交不会清除旧凭据。

---

### User Story 4 - 后续源以同一方式接入 (Priority: P2)

维护者新增一个上游源时，只需要提供该源的描述、配置约束、协议适配、模型目录或健康检查能力，并在应用组装处注册；不需要修改共享调度规则、服务入口、管理框架或为该源增加特判。

**Why this priority**: 架构的价值要体现在下一次扩展成本上，但前提是先稳定现有四种源，因此优先级低于本次可用性行为。

**Independent Test**: 以一个测试源插件接入模拟环境，验证注册后可被配置引用、参与调度、暴露管理元数据，并在取消注册后配置校验失败。

**Acceptance Scenarios**:

1. **Given** 测试源已注册, **When** 操作者使用其稳定 ID 配置源, **Then** 配置通过校验并参与请求分发。
2. **Given** 测试源未注册但配置引用它, **When** 系统加载或热重载, **Then** 变更被拒绝且旧运行状态保持不变。

---

### Edge Cases

- 源类型存在但专属配置缺少凭据、地址或其他必填项时，必须作为配置错误处理，不能等到请求阶段才暴露模糊失败。
- 同一配置文件混排多种源时，每个源必须按自己的类型解析和执行，failover 顺序继续由调度策略决定。
- Copilot endpoint 发现失败必须回退到其声明的默认地址，并把失败上下文写入诊断日志。
- Copilot 模型目录拉取失败必须保留既定回退协议路由，不得替上游判定账户或模型不可用。
- 多个授权流程并发发起时，系统必须保持一个活跃流程并返回冲突状态；取消、保存中和成功后的状态不能允许旧流程覆盖新凭据。
- 热重载读取到未知源类型或无效专属选项时，磁盘加载链路必须整体失败，旧配置和旧运行状态继续服务。
- 观测和管理响应必须携带稳定的源类型身份，但不能包含明文凭据、Authorization、GitHub token 或其他敏感值。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每个源配置 MUST 包含操作者可读的稳定源类型标识；共享核心 MUST NOT 依赖单字符后端代号来表达源身份。
- **FR-002**: 系统 MUST 将源专属设置放入该源的扩展配置区域；通用配置区 MUST 只承载跨源概念，例如名称、启用状态、基础地址、API key、请求头、模型映射、默认模型和熔断覆盖。
- **FR-003**: 系统 MUST 根据已注册源插件校验源类型和专属设置；未注册类型、缺少必填项、类型不符或无法解析的专属值 MUST 导致配置加载或保存失败。
- **FR-004**: 系统 MUST 显式拒绝旧 `backend_type` 表达和位于通用区的历史专属字段；错误信息 MUST 说明新配置形状，MUST NOT 自动迁移或猜测。
- **FR-005**: 共享调度器 MUST 通过统一的源插件契约选择和执行 Backend，禁止为任何具体源类型编写分发分支。
- **FR-006**: Anthropic Messages、OpenAI Chat Completions、OpenAI Responses 和 GitHub Copilot MUST 作为内置源插件注册，且现有流式协议行为、EventGate 语义、终态语义和 failover 语义 MUST 保持不变。
- **FR-007**: GitHub Copilot 的 endpoint 发现、模型目录筛选、协议路由、必需请求头、Device Flow 授权和连通性探测 MUST 全部归属同一个源插件边界；共享核心 MUST NOT 出现 `g`、`github_token` 或 Copilot 文案等专属事实。
- **FR-008**: Copilot 插件 MUST 继续让上游裁决模型权限和协议能力；目录信息只用于选择委托协议，禁止因推断订阅限制而主动拒绝请求。
- **FR-009**: 管理框架 MUST 从源插件获取配置结构和扩展动作描述，并据此渲染、校验和提交源表单；共享管理代码 MUST NOT 为某个内置源写死表单分支。
- **FR-010**: 敏感专属字段 MUST 在管理读取、日志、指标和错误响应中脱敏；保存时空值或明确哨兵值表示保留已有敏感值，直接清空必须使用插件声明的显式清空语义。
- **FR-011**: 上游模型列表和连通性测试 MUST 通过统一入口分派给支持该能力的源插件；不支持某能力的插件 MUST 返回明确的能力缺失结果。
- **FR-012**: 源配置变更 MUST 继续走唯一磁盘真相源和原子替换链路；插件注册表必须在配置加载、管理保存和热重载间提供一致结果。
- **FR-013**: 调度、熔断、降级恢复、客户端取消、首字节超时和整轮重试 MUST 保持平台级职责，不得下沉到单个源插件重复实现。
- **FR-014**: 新增源 MUST 通过实现源插件契约并在唯一组装入口注册完成；为此需要修改的共享核心文件数 MUST 为零（文档登记和组装注册除外）。
- **FR-015**: 项目治理文档、协议矩阵、README 和示例配置 MUST 与新源身份模型同步；章程中的旧硬编码源类型清单 MUST 在实施前修订。

### Key Entities *(include if data involved)*

- **Source**: 一个可调度的上游定义；包含稳定名称、源类型标识、启用状态、通用连接与调度字段、以及类型专属 options。
- **Source Plugin**: 一类上游的能力声明和适配器；提供稳定 ID、标题、配置结构、源校验、请求执行能力，并可选提供模型目录、健康探测和管理扩展。
- **Config Schema**: 源插件公布给管理面的字段描述；包含字段名、类型、必填性、默认值、敏感性和说明。
- **Source Options**: 属于某一源类型的键值集合；由该插件的 schema 解释，共享核心只透传和持久化。
- **Credential Session**: 一次交互式凭据获取流程；具有唯一活跃态、公开进度状态和成功落盘结果，禁止暴露临时授权码或最终凭据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四种内置源在新配置模型下的既有协议回归场景全部通过，其中流式终态、空流换源、4xx 归因和客户端取消场景覆盖率达到 100%。
- **SC-002**: 共享核心目录中可验证的 Copilot 专属标识数量为零；架构守护测试能发现任何新增的直接依赖或专属分支。
- **SC-003**: 管理页无需修改共享源表单即可展示四种内置源的不同字段集合，并在浏览器验收中完成新增、编辑、重新授权和保存刷新。
- **SC-004**: 模拟“新增测试源”改造中，除新插件自身和唯一组装注册外，共享调度、服务入口、管理框架和健康框架的代码改动为零。
- **SC-005**: 所有配置读写路径对未知源类型或无效专属配置的拒绝率为 100%，且热重载失败时不丢失旧运行状态。
- **SC-006**: 日志、指标、管理响应和错误详情的抽样检查中明文凭据出现次数为零。

## Assumptions

- 本特性接受破坏性配置变更；用户负责把本地配置从旧格式迁移为新格式，系统只提供清晰错误，不承担静默兼容。
- 内置源仍然随应用一起发布并注册，本期不要求外部动态加载、进程外插件或热安装。
- 现有调度优先级、熔断阈值、EventGate 和 Responses SSE 对外契约不变。
- GitHub Copilot 的 OAuth client、scope、轮询节奏和默认 endpoint 继续沿用已批准设计。
- 项目章程必须先从“固定 backend_type 清单”修订为“已注册源插件清单”，否则本规格不能进入实现。
